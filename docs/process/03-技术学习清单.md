# 技术学习清单

> 全部为官方文档 / 权威文章，**不含书、不含视频**。所有链接已逐个核对可访问（2026-10-27）。
> 分两档：**必须掌握**＝你要亲手写、并且评审问到时能解释；**必须了解**＝不写代码，但要能讲清原理和取舍（写进 README 的"已知问题/为什么不这么做"要用）。

## A. 必须掌握（13 项）

## C. 阅读顺序（按风险排，不按难易排）

1. **先读 A4 → A5 → A6 → A7 → A8**（约 2 小时）。这是全项目唯一陌生的部分，也是第 1 天就要跑通的部分。读完正好赶上 Android 模块下完。
2. **A11**（1 小时）。打包链路，越早看越早发现缺什么。
3. **A1 → A2 → A3**（1.5 小时）。回过头补 Unity 的心智模型，这时你已经有具体场景了，读起来快得多。
4. **A9 → A10**（1 小时）。表单 + 提交，接后端。
5. **A12 → A13**（各 1 小时）。你熟的领域，只是换成这个项目的具体写法，主要是核对细节（1.22 路由模式、四态渲染）。
6. **B 类按需**：写 README 前集中看 B2 / B3 / B5 / B7，因为这四篇直接决定"已知问题"那一节写得多有说服力。

## D. 明确不用学（省下时间）

- Shader / 材质球调优 / 光照烘焙 —— 作业明确不考察美术
- 动画系统、物理系统、Addressables、Timeline
- Unity 编辑器扩展、自定义 Inspector
- DOTS / ECS / Burst
- iOS 打包（只用 Android）
- AR 云锚点 / VPS 的实操（只用了解成本，不实现）
- Unity 的旧输入系统 vs 新 Input System 之争 —— 用默认的，遇到冲突再说
