# 迭代计划 · 第一遍：只对主流程

> 目标：**一条 happy path 从手机走到网页，中间没有分支、没有异常处理、没有兜底。**
> 这一遍做完，就是演示视频能拍的 5 个镜头。异常、引导、加分项全部留到第二遍。

## 环的契约（三条）

1. **学，20 分钟一篇文档**，只学这个环要用的那一点。
2. **AI 做，一个环一个能跑的东西**，附：怎么跑、看到什么算成功。
3. **我理解，两问 + 一处改动**：不看代码答两问，然后亲手改一处（改文案 / 改数值 / 删一行看它怎么坏）。改不动 = 环不过。

## 四个环

| # | 环 | 学（20 min） | AI 做（产出） | 验收（看到什么算过） | 你理解（两问） |
|---|---|---|---|---|---|
| **L1** | 手机上看得见、认得地面 | ARCore 基本概念（运动跟踪 + 环境识别两节） | Android 模块装好；空白 AR 场景装到手机；平面网格显示 | **手机摄像头画面正常，对着地面慢慢晃，网格出现** | ① 为什么晃手机才出网格？② 白墙为什么不出？ |
| **L2** | 点一下，钉子落地 | AR Foundation · Raycasts | 点击命中平面 → 实例化立方体 → 挂锚点 | **点地面出立方体；转身走两步再回来，立方体还在原地** | ① 为什么不能用 `Physics.Raycast`？② 为什么必须挂锚点？ |
| **L3** | 手机把数据交出去 | UnityWebRequest（一页） | Go 四条接口 + SQLite；Unity 表单三字段 + 提交 | **手机填完提交，`curl` 一查后端多了一条；重启 Go 数据还在** | ① 为什么手机会连不上电脑？② 字段名怎么和后端对上？ |
| **L4** | 网页看见、并能改 | React 四态渲染（核对） | Vite 管理端：列表 + 改状态 | **浏览器刷新看到那条记录；改成 in_progress，后端跟着变** | ① 为什么开发时不用写 CORS？② 改状态的请求发到哪？ |

**L3 和 L4 可以合并**成一个环（React 你熟）。分开只有一个理由：出问题时知道是"手机发不出"还是"网页读不到"。

## 每个环的边界

- **L1 结束**：`ar-client/` 能构建、能装、能看到平面。后两端目录还是空的。
- **L2 结束**：能放物体，坐标还没发出去。
- **L3 结束**：数据在库里，但只有手机端会写。
- **L4 结束**：三端闭环成立，必做项完成约 80%。

每环结束打一个 commit：`L1: plane detection on device` / `L2: raycast placement + anchor` / `L3: submit to go api` / `L4: admin list + status update`。

## 时间

| 天 | 环 | 状态 |
|---|---|---|
| D1 | L1 + L2 | 手机上能放东西（最难的一天，环境问题都在这） |
| D2 | L3 | 两端通了，数据在库里 |
| D3 | L4 | 闭环成立，可以截图了 |
| D4–D5 | 第二遍 | 补异常与加分，录视频，写文档 |

**故意留两天给第二遍。** 第一遍只求"通"，不求"稳"。

## 这一遍明确不做（列出来是为了不心虚）

- 检测不到平面时的引导话术
- 跟踪状态和"能不能放"绑定
- 提交失败的提示与重试
- 后端挂掉时的页面错误态
- 垂直面（墙面）放置
- 上报截图
- 筛选、排序、删除、作废、验收
- 登录、权限

这些不是"忘了"，是"排在第二遍"。README 的"未完成"一栏，内容就是这份清单。

## 第二遍（第一遍通了再开）

按"评委看得见"的顺序挑，不按技术难易：

1. **三个失败面各一句人话**（无平面 / 点不中 / 发不出）—— 题目明文要求
2. **跟踪状态绑定提交按钮** —— 演示时能讲出"我知道它什么时候不可靠"
3. **后端挂掉时页面不白屏** —— 题目明文要求
4. **垂直面** —— 题目举的例子本身就是墙面破损
5. **上报截图** —— 补 BR-05 那个洞

每条都能在视频里演示 10 秒，这才是加分的样子。

"我改了哪里"是题目硬要求的证据，每环都填就不是补作业。

## 返工判据

说不清输入输出 / 改不动 / 有时行有时不行 / 为了跑起来关掉某条校验 —— 任一条出现，退回上一个能跑的 commit。
