# 演示视频录屏脚本

两段视频，各 3–5 分钟。分工：

- **视频一（手机端）**：证明是**真机、真实 AR**，不是屏幕固定贴图——平面检测、放置不飘、填报提交。
- **视频二（电脑端）**：证明**闭环成立且数据真的落库**——刷新看到手机上刚提交的那条、改状态、停后端不白屏、重启后数据仍在。

两段都要拍到的五件事（作业要求）：

| 作业要求 | 在哪段视频 | 时间点 |
|---|---|---|
| 真机识别平面并放置标记 | 视频一 | 00:45 – 01:55 |
| 手机提交问题 | 视频一 | 01:55 – 02:45 |
| React 刷新后看到该问题 | 视频二 | 00:20 – 00:55 |
| React 修改状态 | 视频二 | 00:55 – 01:35 |
| Go 重启后数据仍然存在 | 视频二 | 02:35 – 03:20 |

建议**先录视频一，再录视频二**：视频二要展示的就是视频一里刚提交的那条记录。

## 一、开机前的准备（照顺序执行，约 10 分钟）

### 1. 清空演示数据，让计数从 0 开始

视频里"提交前 0 条、提交后 1 条"比"提交前 7 条、提交后 8 条"有说服力得多。

```powershell
cd C:\Users\17130\.myagents\projects\mino\workspace\ar-device\server
# 先备份，别删
Move-Item data\inspections.db      data\inspections.db.bak-demo      -Force
Move-Item data\inspections.db-wal  data\inspections.db.bak-demo-wal  -Force -ErrorAction SilentlyContinue
Move-Item data\inspections.db-shm  data\inspections.db.bak-demo-shm  -Force -ErrorAction SilentlyContinue
```

### 2. 确认两个端口空着

```powershell
netstat -ano | findstr ":8080 :5173"      # 有输出就记下 PID，taskkill /PID <pid> /F
```

昨天可能残留一个 socket 已死的 vite 监听，别用它。

### 3. 起后端，确认健康

```powershell
$env:PATH = "C:\Users\17130\dev\go\bin;$env:PATH"
$env:GOCACHE = "$env:TEMP\gocache"
go run ./cmd/api
# 另开一个窗口：
curl http://127.0.0.1:8080/api/health
# 期望：{"status":"ok","db":"ok","version":"0.1.0"}
```

### 4. 手机连上并打通转发

```powershell
adb devices                          # 只应有一台，状态是 device 不是 unauthorized
adb reverse tcp:8080 tcp:8080
adb reverse --list                   # 期望看到 UsbFfs tcp:8080 tcp:8080
```

### 5. 起管理端

```powershell
cd ..\admin
npm run dev                          # → http://localhost:5173
```

### 6. 手机设置（容易翻车的地方）

- 亮度拉到最高、关自动亮度；开勿扰模式（避免横幅进画面）。
- 屏幕超时调到 10 分钟，或干脆先别锁屏。
- **别旋转手机**，按 App 内置方向拿着。
- 找一个**有纹理**的地方扫（地砖、木地板、地毯边）；纯白墙面和玻璃扫不出平面，这是 ARCore 的几何限制，不是程序问题。

### 7. 录制方案

| 素材 | 工具 | 备注 |
|---|---|---|
| 手机屏幕 | `adb shell screenrecord --bit-rate 8000000 --time-limit 300 /sdcard/demo1.mp4`，再 `adb pull /sdcard/demo1.mp4` | 也可用手机自带录屏，更省事 |
| 真实环境（手持操作） | 另一台手机 / 相机，竖拍 | 这段是"真机"的证据，别省 |
| 电脑屏幕 | Win + Alt + R（Xbox Game Bar）或 OBS | 1080p / 30fps，浏览器窗口最大化 |
| 后期 | 剪映 / DaVinci | 手机屏幕 + 真实环境做**画中画**，加字幕 |

**音频**：建议无声录屏 + 字幕，或录完自己配画外音。现场解说容易喷麦、卡词，重录成本高。下面每镜的"口播"按字幕稿写，一句一行即可。

**分段录**：每一镜单独录一段，最后按顺序拼。一条录到底的话，中间任何一次卡顿都要从头再来。

## 二、视频一：手机端（目标 3 分 40 秒）

| 镜 | 时间 | 时长 | 画面 | 操作 | 口播 / 字幕 |
|---|---|---|---|---|---|
| 1 | 00:00 | 0:20 | 电脑屏幕：终端里 `go run` 在跑，`curl /api/health` 返回 ok | 敲一次 health 命令 | 三端闭环：Unity 手机端 → Go 后端 → React 管理端。先起后端。 |
| 2 | 00:20 | 0:25 | 手机 App 启动，HUD 顶部三行：`后端 已连接 v0.1.0 · hh:mm:ss`、`Session: SessionTracking`、`Planes: 0` | 缓慢平移手机 | 顶部常驻后端状态；手机自己建立坐标系，此时它还不知道地面在哪。 |
| 3 | 00:45 | 0:40 | HUD 里 `Planes` 从 0 变 2、3，屏幕上出现平面网格 | 对着地面**缓慢左右晃**，别甩 | ARCore 靠移动产生的视差算深度，所以必须动起来。纯白墙面扫不出来，这是几何限制。 |
| 4 | 01:25 | 0:30 | 点击后出现**橙色方块**，HUD 的 `已放置` +1 | 点一下平面放方块，然后**转身走两步再回来** | 点在平面上，挂到锚点上。走开再回来它还在原位，说明是真 3D 锚定，不是贴图。 |
| 5 | 01:55 | 0:50 | 弹出表单：标题、描述、优先级（低/中/高），点提交 | 填「3 号楼二层走廊 墙面破损」/「踢脚线上方裂缝约 30cm」/选「高」→ 提交 | 标题必填、优先级三档。提交的坐标就是刚才点下去那一点。 |
| 6 | 02:45 | 0:35 | 顶部提示 `已上报 insp_xxx`，方块**变绿** | 停顿 2 秒让提示看清 | 后端返回整条记录，方块变绿表示这条真的落库了。 |
| 7 | 03:20 | 0:20 | 再点一下放第二个标记，选「低」提交 | 放第二个「低」优先级的 | 同一条链路可以连续上报；这个动作也让电脑端统计变成 2 条。 |

**可选加镜（有 20 秒余量时拍）——失败路径，正对评分里"遇到问题能定位修正验证"：**

0. 先演示一次取消：放一个方块后点「取消」→ 方块连同锚点一起消失，`已放置` 计数回落（方块与表单是一体的，不是独立贴纸）；`n1. 电脑上执行 `adb reverse --remove tcp:8080`；
2. 手机上再提交一次 → 顶部报「连不上后端服务」，**已填内容不清空**；
3. 恢复 `adb reverse tcp:8080 tcp:8080`，再点提交 → 成功。

字幕：转发断了，顶部状态变红、提交明确报错且不清空表单；恢复转发后点「重连后端」，状态立刻回绿，原样重试即可。这条转发在 USB 重连、锁屏后会掉。

## 三、视频二：电脑端（目标 3 分 50 秒）

| 镜 | 时间 | 时长 | 画面 | 操作 | 口播 / 字幕 |
|---|---|---|---|---|---|
| 1 | 00:00 | 0:20 | 终端：`go run` 在跑；浏览器标签页还空着 | 敲一次 health | 手机刚提交的那条，现在在电脑上看。 |
| 2 | 00:20 | 0:35 | 管理端首页：顶栏徽章「服务正常 · v0.1.0」、四个统计卡、列表 | 打开 http://localhost:5173，点一次「刷新」，指一下「最后同步 hh:mm:ss」 | 统计是全部 2、待处理 2（视频一第 7 镜放了第二条）。列表由后端按创建时间倒序返回，前端不再排序。 |
| 3 | 00:55 | 0:40 | 详情抽屉「问题详情」 | 点列表里手机提交的那行，抽屉展开（标题、描述、优先级「高」、坐标三位小数、两个时间） | 坐标是手机上报的原始值，单位米。详情不做成独立页面，因为契约里没有 `GET /:id`。 |
| 4 | 01:35 | 0:30 | 「修改处理状态」下拉 | 选「处理中」 | v1 只能改状态，标题和优先级不可编辑，这是契约冻结点。 |
| 5 | 02:05 | 0:30 | 行内状态变「处理中」，统计卡跟着变；展开底部「请求日志（核验用，最近 30 条）」 | 展开日志，指 PATCH 那条：请求体 `{"status":"in_progress"}`、响应体整条记录、`updatedAt` 已刷新 | 界面在拿到响应之后才变，不做乐观更新。日志里是原始请求和响应，可以逐字节核对。 |
| 6 | 02:35 | 0:30 | 「契约与状态」页 | 点顶栏导航 | 四个端点、四个错误码以及它们各自在页面上的落点。这页只读，不产生写操作。 |
| 7 | 03:05 | 0:45 | 终端 Ctrl+C 停掉后端 → 回浏览器点「刷新」 | 停后端，刷新页面 | 后端挂了：徽章变「未连接后端」，页面不白屏，给出错误和重试按钮。 |
| 8 | 03:50 | 0:30 | 重启 `go run` → 点「重试」或「刷新」→ 数据还在，那条仍是「处理中」 | `curl /api/inspections` 显示两条记录 | SQLite 落盘，重启后数据还在，状态也没丢。 |
| 9 | 04:20 | 0:20 | 终端：`go test ./...` 与冒烟脚本的通过行 | 跑一次冒烟（可选，几秒） | 34 项契约冒烟、13 项单测全绿。 |

总长 4 分 40 秒，在 3–5 分钟范围内。赶时间就砍第 9 镜。

## 四、录完自检（对着打勾，别凭印象）

- [ ] 画面里能看出是**真机**：手机屏幕之外有真实环境（画中画或手持镜头），不是纯录屏
- [ ] 平面上出现网格，`Planes` 计数真的变了
- [ ] 方块**转身回来还在原位**（这段不能剪掉，是"锚定"的唯一证据）
- [ ] 提交后出现 `已上报 insp_xxx`，方块变绿
- [ ] 电脑端**刷新**之后才看到那条（要求原话就是"刷新后看到"，别用自动轮询蒙过去）
- [ ] 改状态后统计卡与行内状态同时变
- [ ] 停后端后页面**不白屏**、有错误提示与重试
- [ ] 重启后那条记录还在，且状态是改后的「处理中」
- [ ] 两段各 3–5 分钟；画面里无隐私信息（邮箱、账号、token、其他窗口）
- [ ] 没有报错弹窗、没有无关聊天窗口、没有 IM/视频软件通知

## 五、常见翻车与兜底

| 症状 | 原因 | 处理 |
|---|---|---|
| 手机报「连不上后端服务」 | `adb reverse` 被清空（USB 重连、锁屏、重装） | 重新 `adb reverse tcp:8080 tcp:8080`，代码不用动 |
| 一直扫不出平面 | 对着白墙或玻璃；或手机没动 | 换有纹理的地面，缓慢平移而不是原地转 |
| 点一下没反应 | 点在了没检测到平面的位置 | 等网格出现再点，点网格内部 |
| 方块飘走 | 跟踪丢失（太暗或移动过快） | 重开 App 重新扫；录像时动作放慢 |
| 8080 被占用 | 之前 `go run` 没退 | `netstat -ano \| findstr :8080` 找到 PID，`taskkill /PID <pid> /F` |
| 5173 打开是白的 | 残留的死 vite 进程 | 杀掉重启，或 `npm run dev -- --port 5174` |
| 列表里一堆旧测试数据 | 没清库 | 按准备第 1 步移走 `inspections.db*` 再起后端 |
| 录完发现某镜口误 | —— | 只重录那一镜再拼，别整段重来 |
